What it does

Most time-series demos show a fitted line and stop. The hard parts are before and after: is the data trustworthy? Which model is actually best — proven out-of-sample, not just tuned? How confident is the forecast? And so what — what should a business do next? ForecastEngine makes that whole loop explicit, honest, and testable.

The system, end to end

1
Validate

Schema, temporal-integrity, and target-quality checks produce an explicit issue list and a Data Quality Score. Nothing is silently modified — every transformation is reported.

app/data/validator.py
2
Preprocess

Parse and sort dates, deduplicate timestamps, and coerce the target to numeric with a full record of actions.

app/data/preprocessing.py
3
Explore

Automated EDA — statistically tested trend, weekly + yearly seasonality (period and strength), volatility trend, and anomalies.

app/analysis/eda.py · seasonality.py · anomalies.py
4
Feature engineering

Calendar, lag, and rolling features with a strict no-future-leakage design (lag = 1 minimum).

app/features/engine.py
5
Backtest

Expanding-window validation (4 folds) over five families — naive · seasonal naive · ETS · auto-SARIMA · XGBoost — ranked on a configurable metric; the winner is selected out-of-sample, never on a random split.

app/evaluation/backtesting.py
6
Forecast + uncertainty

Retrains the winner on full history, produces horizon forecasts with prediction intervals (native when available, otherwise a documented approximation), plus expected-change direction.

app/models/ · app/forecasting/pipeline.py
7
Explain & decide

Driver signals (trend · seasonality · volatility), feature importance (SHAP optional), and a plain-language brief — rule-based by default, with an optional AI layer behind a feature flag. No API key required to run.

app/explainability/ · app/ai/

Honest limitations

A portfolio demonstration, and I'm upfront about it:

  • Synthetic data — the sample is generated from a business-demand model (seed 42); real CSV/XLSX can be uploaded through the API or dashboard without code changes.
  • Forecasts are probabilistic expectations, not causation — driver signals describe statistical association only; no causal analysis is performed.
  • Recursive long-horizon forecasting compounds error — for XGBoost the horizon is built step-by-step; intervals for models without native uncertainty are documented approximations.
  • Classic ML only — no deep learning or foundation-model forecasting; deliberately fast and interpretable.
  • AI layer is opt-in — requires AI_ENABLED=true + OPENAI_API_KEY; otherwise the fully deterministic rule-based engine is used.
